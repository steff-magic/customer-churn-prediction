# Прогнозирование оттока клиентов телекоммуникационной компании

## Описание проекта

Проект посвящён разработке модели машинного обучения для прогнозирования оттока клиентов телекоммуникационной компании.

Цель — определить клиентов, которые с высокой вероятностью могут отказаться от услуг компании. Такая модель может помочь бизнесу заранее выявлять потенциально уходящих клиентов и принимать меры для их удержания.

В рамках проекта выполнены исследовательский анализ данных, предобработка признаков, обучение нескольких моделей классификации, подбор порога классификации и итоговая оценка качества на тестовой выборке.

## Постановка задачи

Необходимо решить задачу бинарной классификации:

- `0` — клиент остаётся с компанией;
- `1` — клиент прекращает пользоваться услугами компании.

В качестве целевого признака используется `Churn`.

## Датасет

Используется набор данных **Telco Customer Churn**.

Датасет содержит информацию о клиентах телекоммуникационной компании: сведения о договорах, подключённых услугах, платежах и продолжительности обслуживания.

- Количество записей: 7043.
- Целевой признак: `Churn`.
- Идентификатор клиента `customerID` исключён из обучения модели.

Исходный CSV-файл необходимо самостоятельно разместить в папке `data/`.

## Этапы работы

### 1. Первичный анализ данных

- Изучение структуры и размера датасета.
- Анализ типов признаков.
- Изучение распределения целевой переменной.
- Проверка основных статистических характеристик.

### 2. Проверка качества данных

- Поиск дубликатов.
- Проверка пропущенных значений.
- Обработка некорректных значений в `TotalCharges`.
- Исключение идентификатора клиента из признакового пространства.

### 3. Исследовательский анализ данных (EDA)

- Анализ оттока клиентов в зависимости от типа договора.
- Исследование связи продолжительности обслуживания с оттоком.
- Анализ ежемесячных платежей.
- Формулирование предварительных выводов.

### 4. Предобработка данных

- Разделение данных на обучающую и тестовую выборки.
- Выделение числовых и категориальных признаков.
- Заполнение пропущенных значений с помощью `SimpleImputer`.
- Кодирование категориальных признаков с помощью `OneHotEncoder`.
- Масштабирование числовых признаков с помощью `StandardScaler`.
- Объединение этапов предобработки в `ColumnTransformer` и `Pipeline`.

### 5. Обучение и оценка моделей

В проекте рассматриваются следующие модели:

- `DummyClassifier` — базовая модель для сравнения.
- `LogisticRegression` — линейная модель классификации.
- `RandomForestClassifier` — ансамблевая модель на основе решающих деревьев.

Для сравнения используются метрики:

- Accuracy
- Precision
- Recall
- F1-score
- ROC-AUC

Для выбора модели и настройки порога классификации используется валидационная выборка. Тестовая выборка сохраняется для итоговой оценки.

### 6. Подбор порога классификации

Дополнительно исследуется влияние порога классификации на Precision и Recall.

Выбранный порог: `0.3`.

Такой выбор ориентирован на повышение Recall — способности модели находить клиентов, которые действительно могут уйти. Это позволяет уменьшить количество пропущенных случаев оттока, однако увеличивает количество ложноположительных предсказаний.

Порог выбран с учётом предполагаемого бизнес-приоритета, а не как универсально оптимальное значение.

### 7. Сохранение модели

Обученный Pipeline сохраняется с помощью Joblib. Отдельно сохраняется выбранный порог классификации.

Это позволяет использовать модель без повторного выполнения всех этапов обучения.

## Ограничения проекта

- Используется один датасет, поэтому результаты не гарантируют аналогичного качества на других данных.
- Подбор гиперпараметров моделей не является исчерпывающим.
- Выбранный порог классификации основан на предполагаемом приоритете Recall, а не на расчёте реальных финансовых потерь бизнеса.
- Выявленные зависимости между признаками и оттоком не означают наличие причинно-следственной связи.
